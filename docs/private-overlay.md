# Private overlay v1

Default CONTENT_MODE=sample reads only content/sample. Private mode requires PRIVATE_OVERLAY_ROOT outside the checkout, PRIVATE_OVERLAY_REVISION (40 hex characters) and PRIVATE_OVERLAY_DIGEST (SHA256 of manifest.json bytes). A manifest contains schemaVersion: 1, revision, and files mapping every required relative path to its SHA256. See REQUIRED_CONTENT in lib/content-overlay.mjs for the complete list.

Missing, changed, malformed, incomplete or escaped files fail closed before any private file is served. No sample fallback or fetch token is used. Private prebuild validates the external snapshot and writes only the validated bytes to the ignored .content-runtime server payload. Runtime validates that payload against the same pinned digest and revision. Sample prebuild removes the payload and previous build cache; sample server traces exclude private runtime files. Tests and demos force samples. Preview private mode is refused. Private writers require a separate external CONTENT_WRITE_ROOT and cannot mutate an immutable overlay snapshot. Create and review a new snapshot and digest after writing.

Production requires the canonical Vercel project, GitHub repository ID/owner/name, protected main branch, actual provider commit and deployment IDs, and private mode. The trusted build validates those provider fields and writes an immutable server-only release stamp. Runtime checks that stamp against the same provider identity and immutable data pins. Normal protected-main merges receive their own provider-bound stamp without manually changing a source SHA setting. An optional PRIVATE_RELEASE_SHA remains available as an additional exact source constraint; a configured mismatch fails closed. The stamp binds a deployment; protected-branch review and required CI establish source trust.

Operational runtime configuration is separately supplied as runtime.json, schemaVersion 1, pinned by PRIVATE_RUNTIME_DIGEST. It contains calendar account bindings, publication mappings, the reviewed offer/candidate configuration and brand/mail presentation defaults. The public sample is config/runtime.sample.json; its schema and the server-only loader are lib/runtime-config.mjs. Private data never replaces executable source files, and client components receive only the selected authorized presentation data.

Configure the production provider install command as `node scripts/production-install.mjs` and build command as `node scripts/production-build.mjs`. Installation first removes restored private build payloads/caches, then installs the full locked dependency set with lifecycle scripts disabled, an allowlisted environment and a temporary home directory. This prevents dependency lifecycle execution during installation; environment scrubbing alone is not an operating-system sandbox.

The build fetches the exact PRIVATE_CONTENT_REVISION from the single dedicated PRIVATE_CONTENT_REPOSITORY using a read-only repository deploy key in PRIVATE_CONTENT_SSH_KEY. It pins GitHub's published SSH host key, rejects non-regular/executable/unexpected tree entries, and accepts only the nineteen overlay JSON files, manifest.json and runtime.json. The overlay manifest revision/digest and runtime digest are independently validated before materialization. Fetch credentials are removed before Next runs; temporary key files and checkout are removed on success or failure. Failed builds also remove generated private payloads.

Where organization policy disables deploy keys, use the dedicated protected data project's immutable PRIVATE_CONTENT_URL instead. PRIVATE_CONTENT_READ_TOKEN is a read credential scoped only to that data project; it is sent in the protection-bypass header, never a URL. The HTTPS gzip artifact is pinned by PRIVATE_CONTENT_BUNDLE_DIGEST and contains schemaVersion 1, the exact private revision, and a files map of the same twenty-one paths to base64 original bytes. The loader rejects redirects, URL aliases/query/credentials, unexpected paths, noncanonical base64, oversized responses/files and gzip expansion beyond its limit. Overlay and runtime hashes remain independently required. The release stamp additionally binds the exact artifact URL and compressed digest. The data project must require authentication for every deployment; verify unauthenticated denial and authorized reads before use. The fetching token is removed before Next runs.

Keep the deploy key production-scoped, with no public CI/fork/preview access. Disable untrusted preview execution on the production project; use a separate sample project for public previews. Do not provide a broad repository or hub read token. The ignored .content-runtime payload and release stamp are traced only into server output, and must not enter public artifacts, client bundles or shared sample caches. Keep the prior deployment serving until the staged candidate passes its runtime and authorization checks; a local build alone does not establish deployed health.
